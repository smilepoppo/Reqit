# Reqit 実装計画

この文書は Reqit の実装計画と進捗を管理します。完了条件を満たし、検証が済んだ項目だけにチェックを付けます。

- 状態の凡例：`[x]` 完了（検証済み）／`[ ]` 未着手または未完了／`[~]` 一部完了
- 「検証」欄には、実際に実行した確認方法を書きます。未検証の項目は完了扱いにしません。

## 2. 既存 OSS との比較（要約）

以下は開発者の既知情報に基づく整理です。各製品の最新仕様は公開前に再確認します。

| 製品       | 形態                     | Reqit との違い                                                   |
| ---------- | ------------------------ | ---------------------------------------------------------------- |
| Postman    | Electron、アカウント中心 | 多機能だが起動が重い。Reqit はアカウント不要・1画面              |
| Insomnia   | Electron                 | 同上。クラウド同期が前提になりつつある                           |
| Bruno      | Electron、ファイルベース | コレクション管理が中心。Reqit は単発の動作確認とデバッグが中心   |
| Hoppscotch | Web / PWA                | ブラウザ版は CORS の制約を受ける。Reqit はネイティブ通信         |
| Yaak       | Tauri                    | 軽量志向で近い。Reqit は内蔵ブラウザの通信取得と差分比較で差別化 |

Reqit の差別化要素は「内蔵ブラウザで発生した通信を取り込み、編集・再送信・比較できること」です（v0.3）。

## 5. 開発環境で確認したこと

開発は Linux のクラウドコンテナでも行っています。そのため、次の点に注意します。

- Windows 向けビルドとインストール確認は GitHub Actions（`windows-latest`）で行う
- 起動時間とメモリ使用量は、Windows 実機で測定するまで「未測定」と記載する
- Linux では Windows Credential Manager の代わりに keyring のモック実装が使われ、秘密情報は永続化されない
