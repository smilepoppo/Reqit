# 性能測定

## 目標

- 起動後すぐに URL を入力できること
- 常駐時のメモリ使用量を小さく保つこと
- 大きなレスポンス（数 MB 以上）を受信しても UI が固まらないこと

## Windows 11（WebView2）

**未測定です。** Windows 11 実機で測定した結果をここに追記します。

測定方法（予定）：

1. `pnpm tauri build` で作成したリリース版を使う
2. 起動からウィンドウ表示まで、および URL 欄が操作可能になるまでの時間を 5 回測定する
3. タスクマネージャーで、Reqit 本体と WebView2 の子プロセス（`msedgewebview2.exe`）のメモリ（プライベートワーキングセット）を合計する

## 参考：Linux（WebKitGTK、開発用コンテナ）

Windows の値の代わりにはなりません。WebView のエンジンが異なり、GPU がないためソフトウェア描画です。

| 項目                               | 結果                        | 測定方法                                                                 |
| ---------------------------------- | --------------------------- | ------------------------------------------------------------------------ |
| 起動からウィンドウ表示まで         | 76〜91 ms（5 回）           | プロセス起動から X ウィンドウ「Reqit」が現れるまで（Xvfb）               |
| URL 欄が操作可能になるまで         | 約 0.9〜1.3 秒              | WebDriver のセッション作成から要素取得まで（WebDriver の準備時間を含む） |
| メモリ（アプリ本体）               | RSS 約 154 MB               | `/proc/<pid>/smaps_rollup`                                               |
| メモリ（本体 + WebKit 子プロセス） | PSS 約 360 MB               | 同上。ソフトウェア描画（llvmpipe）の分が含まれる                         |
| 実行ファイルのサイズ               | 約 6.2 MB                   | `target/release/reqit`（Linux、strip 済み）                              |
| フロントエンドの JS                | 約 584 KB（gzip 約 185 KB） | `dist/assets/*.js`                                                       |

### 大きなレスポンスの表示（Linux、E2E スモークテストで測定）

送信ボタンを押してからステータスが表示されるまでの時間です。表示後にタブを切り替えられること（UI が固まっていないこと）も確認しています。

| -------------------------- | --------- | ------------------------------------------------------- |
| 約 2.8 MB の JSON（1 行）  | 約 0.5 秒 | 整形して表示                                            |

測定日：2026-11-19。

## 大きなレスポンスへの対策

- 本文の読み込みは 20 MiB で打ち切り、切り詰めたことを表示する（`crates/reqit-core/src/engine.rs`）
- 5 MiB を超える JSON は整形せずに表示する（`src/lib/format.ts`）
- 表示には CodeMirror 6 を使い、表示範囲だけを描画する
- 512 KiB を超える本文は折り返さずに表示する。巨大な 1 行を折り返すと描画に時間がかかるため
